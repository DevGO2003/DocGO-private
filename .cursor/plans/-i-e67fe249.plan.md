# Kế hoạch điều chỉnh luồng upload/download và metadata

## Mục tiêu

- Automation Service: chịu trách nhiệm upload/download file và xử lý (OCR/AI), publish event.
- File Management Service: lưu metadata/tài liệu theo event để trả về schema giàu dữ liệu (tham chiếu `documents/architecture/api-response-sample.json`).
- Chuẩn hóa cấu hình kích thước, loại file; ghi chú CORS ở API Gateway; tuân thủ `.cursor/rules`.

## Thay đổi chi tiết

### 1) API Gateway (Next.js)

- File: `backend/api-gateway/pages/api/files/upload.ts`
- Hành động:
- Giữ nguyên parse multipart với formidable.
- Thêm comment bắt buộc: frontend chỉ gọi qua gateway, không gọi microservice trực tiếp.

### 2) Automation Service (FastAPI)

- Files: `backend/automation-service/file_router.py`, `backend/automation-service/services/file_service.py`, `backend/automation-service/config.py`
- Hành động:
- Giữ upload vật lý (local/S3) và download tại Automation (theo chỉ đạo mới).
- Loại bỏ/tạm vô hiệu hóa HTTP POST JSON sang File Service trong `upload_document` và thay bằng publish Kafka event "DocumentCreated/FileUploaded" theo chuẩn `.cursor/rules/02_event-exception-standards.mdc`.
- Event payload: gồm `documentId|fileId`, `fileUrl`, `filename`, `size`, `contentType`, OCR/classification/summary (nếu có) để File Service dựng metadata đầy đủ.
- Bật/tôn trọng `KAFKA_ENABLED`; nếu Kafka down: log + không chặn flow (best-effort), sau này có thể nâng cấp outbox.

### 3) File Management Service (FastAPI)

- Files: `backend/file-management-service/routers.py`, `backend/file-management-service/services/file_service.py`, `backend/file-management-service/config.py`
- Hành động:
- Sửa config:
  - Sửa loader `.env` bị lệch indent (tabs/spaces) để tránh lỗi runtime.
  - Đổi `MAX_FILE_SIZE` sang số bytes 2GB và sử dụng tên `MAX_FILE_SIZE_BYTES`.
  - Bổ sung `ALLOWED_FILE_TYPES` trong `Config`.
- Router upload multipart vẫn giữ để test trực tiếp (dev), nhưng nguồn sự thật về metadata đến từ event.
- Thêm Kafka consumer: nhận event từ Automation, map sang model metadata và lưu; API `GET` trả theo envelope chuẩn, tiến dần tới schema giàu dữ liệu (bám `documents/architecture/api-response-sample.json`).
- Kafka consumer để ở module riêng (ví dụ `services/event_consumer.py`) với handler idempotent theo `eventId`/`correlationId`.

### 4) Chuẩn hóa phản hồi và CORS

- Đảm bảo mọi response bọc `RestResponse` (đã có); không dùng HTTP 204 (theo rule).
- Ghi chú comment CORS tại Gateway route upload.

### 5) Kiểm thử

- Script: dùng `test-upload-flow.sh` qua Gateway để xác nhận:
- Upload <2MB (201 sync) và >=2MB (202 async).
- Kiểm tra Automation download endpoint hoạt động.
- Sau khi Kafka chạy, gọi File Service `GET` chi tiết để thấy metadata khớp sample.

## Bổ sung chỉnh sửa cụ thể (áp dụng ngay)

1) backend/file-management-service/config.py

- Sửa indent .env loader (tránh lỗi tabs/spaces), thêm parser kích thước.
- Đổi MAX_FILE_SIZE sang bytes (2GB) bằng hằng số `MAX_FILE_SIZE_BYTES`.
- Thêm `ALLOWED_FILE_TYPES` (list từ env, mặc định: pdf,docx,txt,jpg,jpeg,png,gif).

2) backend/file-management-service/routers.py

- Dùng `FMConfig.MAX_FILE_SIZE_BYTES` và `FMConfig.ALLOWED_FILE_TYPES` từ `config.Config` thay vì biến lẻ.
- Sửa chỗ compare size: `if file.size and file.size > FMConfig.MAX_FILE_SIZE_BYTES: ...`.

3) backend/api-gateway/pages/api/files/upload.ts

- Thêm comment rõ: Frontend CHỈ gọi API Gateway; không gọi microservice trực tiếp.

4) backend/automation-service/file_router.py (Kafka thay HTTP JSON)

- Sau khi upload (local/S3) thành công: publish event Kafka `DocumentCreated`/`FileUploaded` theo chuẩn `.cursor/rules/02_event-exception-standards.mdc`.
- Nội dung event bao gồm: `documentId|fileId`, `fileUrl`, `filename`, `size`, `contentType`, và các trường OCR/classification/summary nếu có.
- Tạm giữ HTTP fallback (flag) nếu Kafka tắt.

5) Dọn chồng chéo lưu trữ

- Ngắn hạn: Automation vẫn upload & download; hướng người dùng dần sang download qua File Service.
- Dài hạn: bỏ phần write local/S3 trong `automation-service/services/file_service.py`; chuyển sang multipart cho File Service hoặc chỉ publish Kafka để File Service tự lưu.

6) Gợi ý Kafka "tốt nhất hiện tại"

- Giữ best-effort (không chặn upload nếu Kafka down).
- Bật/ẩn bằng `KAFKA_ENABLED`.
- Log lỗi có `correlationId`.
- Lộ trình sau: outbox pattern để đảm bảo độ bền.
