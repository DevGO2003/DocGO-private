# Triển khai Commenting & Collaboration Service (FastAPI CRUD thread/comment)

## Prompt
```
Bạn là senior backend engineer. Hãy triển khai `commenting-collaboration-service` bằng FastAPI (thay vì NestJS) cho DocGO theo chuẩn dự án.

MỤC TIÊU (SCRUM-121): Chốt stack FastAPI và tạo đầy đủ CRUD cho thread/comment, hỗ trợ ContractDetailView và Gateway WS về sau.

QUY TẮC CHUẨN HÓA (DocGO):
- Base path: `/api/v1/commenting-collaboration-service`
- Tài nguyên: số nhiều, kebab-case: `threads`, `comments`
- Envelope `RestResponse` thống nhất; quy tắc 204 trong body, không dùng HTTP 204
- Docs tại `/docs#/` với summary/description tiếng Việt + phần Đầu vào/Đầu ra
- Exception handlers 400/404/409/500; unexpected → `RestResponse` 500
- Cấu trúc: `main.py`, `routers/`, `schemas/`, `services/`, `config.py`, `README.md`, `How to run this microservice.md`
- Port cố định: 8005 (theo bảng port DocGO)

ENDPOINTS YÊU CẦU:
THREADS
1) `POST /threads` – tạo thread gắn `contractId`
   - Body: { contractId, title, createdBy, participants?: [userId] }
   - Trả `RestResponse<Thread>`
2) `GET /threads` – liệt kê thread theo bộ lọc (contractId, createdBy) + phân trang
3) `GET /threads/{threadId}` – chi tiết thread (kèm lastMessageAt, totalComments)
4) `PUT /threads/{threadId}` – cập nhật title/participants
5) `DELETE /threads/{threadId}` – xoá mềm thread (includeDeleted=true sẽ thấy)

COMMENTS
6) `POST /threads/{threadId}/comments` – tạo comment
   - Body: { content, attachments?: [fileId], mentionedUserIds?: [userId] }
7) `GET /threads/{threadId}/comments` – phân trang comments (sortBy createdAt, asc/desc)
8) `PUT /comments/{commentId}` – chỉnh sửa comment (lưu version cũ vào history)
9) `DELETE /comments/{commentId}` – xoá mềm comment

BỔ SUNG (chuẩn bị cho realtime/Gateway WS):
- Event Payload Standard: phát `CommentCreated`, `CommentUpdated`, `CommentDeleted` (data: threadId, commentId, actor, mentions, attachments)
- Lưu `editHistory` cho comment: [ { editedAt, editorId, before, after } ]
- Mentions: validate userId tồn tại nếu có tích hợp User service
- Attachments: lưu fileId liên kết tới File Storage Asset Service

SCHEMAS GỢI Ý (pydantic):
- Thread { id, contractId, title, participants: [userId], createdBy, createdAt, updatedAt, deletedAt?, lastMessageAt?, totalComments }
- Comment { id, threadId, content, authorId, createdAt, updatedAt, deletedAt?, attachments: [fileId], mentionedUserIds: [userId], editHistory: [...] }
- CreateThreadRequest, UpdateThreadRequest, CreateCommentRequest, UpdateCommentRequest
- PaginatedResponse<T>

SERVICE LAYER:
- `CollaborationService`:
  - `create_thread(req) -> Thread`
  - `list_threads(filters, pagination) -> PaginatedResponse[Thread]`
  - `get_thread(thread_id) -> Thread`
  - `update_thread(thread_id, req) -> Thread`
  - `delete_thread(thread_id) -> bool`
  - `create_comment(thread_id, req, actor_id) -> Comment`
  - `list_comments(thread_id, pagination, sort) -> PaginatedResponse[Comment]`
  - `update_comment(comment_id, req, actor_id) -> Comment`
  - `delete_comment(comment_id, actor_id) -> bool`
- Quy tắc chỉnh sửa/xoá: chỉ author hoặc admin; lưu `editHistory`

ROUTER LAYER:
- `router = APIRouter(prefix="/api/v1/commenting-collaboration-service", tags=["Commenting Collaboration Service"])`
- Thêm summary/description tiếng Việt chi tiết Input/Output theo chuẩn dự án

EXCEPTION/ENVELOPE:
- Dùng `RestResponse` đồng nhất với các service FastAPI hiện có
- Gắn exception handlers như `user-management-service`

DOCKER DEV:
- Dockerfile FastAPI chuẩn; compose dev mount code; port 8005

TÀI LIỆU:
- README + How-to-run (env, docs URL), ví dụ request/response

KIỂM THỬ NHANH:
- Tạo một thread cho `contractId` giả lập → thêm 3 comments → chỉnh sửa comment thứ 2 → liệt kê history/sort
```

## Mục đích
- Cung cấp prompt triển khai đầy đủ service cộng tác (threads/comments) bằng FastAPI theo chuẩn DocGO, sẵn sàng tích hợp realtime và Gateway WS.
