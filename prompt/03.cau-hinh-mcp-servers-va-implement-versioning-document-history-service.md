# Cấu hình MCP Servers và Implement Versioning Document History Service

## Prompt
```
Bạn là senior backend engineer. Hãy triển khai microservice FastAPI `versioning-document-history-service` cho DocGO theo chuẩn dự án hiện có, và đồng thời cấu hình MCP servers trong Cursor để thao tác DB qua chat.

YÊU CẦU CHUNG (theo chuẩn DocGO):
- Base path: `/api/v1/versioning-document-history-service`
- Envelope response: dùng `RestResponse` đồng nhất (apiVersion, statusCode, shortMessage, description, data, timestamp, requestId, path)
- Quy tắc 204: Không trả HTTP 204; luôn HTTP 200 với `statusCode: 204` trong body khi không có dữ liệu
- Docs: Swagger tại `/docs#/` với summary/description tiếng Việt + phần Đầu vào/Đầu ra rõ ràng
- Exception: map 400/404/409/500; unexpected error → `RestResponse` 500 có requestId/timestamp/path
- Cấu trúc FastAPI theo services hiện có: `main.py`, `routers.py` hoặc `routers/`, `config.py`, `schemas/`, `services/`, `README.md`, `How to run this microservice.md`
- Tuân thủ query phân trang: `pageNumber`, `pageSize`, `sortBy`, `sortDirection`, `searchTerm`, `includeDeleted`

NGHIỆP VỤ PHẢI CÓ (4 endpoints chính):
1) `GET /snapshots` – danh sách snapshot theo bộ lọc (contractId, version range, actor)
   - Hỗ trợ phân trang đầy đủ
   - Trả `RestResponse<PaginatedResponse<Snapshot>>`, hoặc `statusCode: 204` khi rỗng
2) `GET /{contractId}/history` – timeline các sự kiện phiên bản (created/updated/approved/signed/...)
   - Có thể lọc theo thời gian, actor, eventType
   - Trả `RestResponse<List<HistoryEvent>>` hoặc `statusCode: 204`
3) `POST /{contractId}/diff` – so sánh hai version (v1, v2)
   - Body: `{ "leftVersion": number, "rightVersion": number, "mode": "text|json|semantic" }`
   - Trả `RestResponse<DiffResult>` (bao gồm summary + danh sách thay đổi)
4) `PUT /{contractId}/restore` – khôi phục hợp đồng về một version cụ thể
   - Body: `{ "version": number, "reason": string }`
   - Trả `RestResponse<RestoreResult>`; đồng thời phát sự kiện chuẩn (Event Payload Standard)

SCHEMAS GỢI Ý (pydantic):
- Snapshot { snapshotId, contractId, version, createdAt, createdBy, checksum, size, note }
- HistoryEvent { eventId, contractId, version, eventType, actor, timestamp, metadata }
- DiffRequest { leftVersion, rightVersion, mode }
- DiffResult { leftVersion, rightVersion, summary, changes: [ { path, changeType, before, after } ] }
- RestoreRequest { version, reason }
- RestoreResult { contractId, restoredFromVersion, newVersion, status, note }
- PaginatedResponse<T>

SERVICE LAYER:
- `VersioningService` với các hàm rõ nghĩa:
  - `list_snapshots(...) -> PaginatedResponse[Snapshot]`
  - `get_history(contract_id, ...) -> List[HistoryEvent]`
  - `compute_diff(contract_id, left, right, mode) -> DiffResult`
  - `restore_version(contract_id, version, reason, actor) -> RestoreResult`
- Kết nối kho dữ liệu (MariaDB/Postgres) và optionally lưu raw diff/history ở Mongo để debug (theo conventions trong repo)
- Phát event theo Event Payload Standard sau khi `restore`

ROUTER LAYER (ví dụ chữ ký):
- `router = APIRouter(prefix="/api/v1/versioning-document-history-service", tags=["Versioning Document History Service"])`
- Thêm summary/description + phần Đầu vào/Đầu ra tiếng Việt cho mỗi endpoint (như các service FastAPI trong dự án)

EXCEPTION HANDLERS:
- Dùng pattern của `user-management-service/main.py`: gắn `http_exception_handler`, `validation_exception_handler`, `general_exception_handler`

RESPONSE ENVELOPE:
- Dùng cùng `RestResponse` như `ai-processing-service` và `file-storage-asset-service` (giữ fields, timestamp ISO-8601, requestId)

DOCKER DEV:
- Cổng cố định: 8004 (theo bảng port DocGO)
- Dockerfile FastAPI chuẩn, và docker-compose.dev mount code (hot reload)

TÀI LIỆU:
- Cập nhật `How to run this microservice.md` (env, run uvicorn, docker compose, docs URL)
- README có mô tả endpoints, ví dụ request/response

KIỂM THỬ NHANH:
- Tạo vài snapshot mẫu, history events giả lập
- Trả `statusCode: 204` trong body khi rỗng, không dùng HTTP 204

—
PHẦN 2: Tạo cấu hình MCP Servers trong Cursor để thao tác DB qua chat

YÊU CẦU:
- Tạo hoặc cập nhật file `.cursor/mcp.json`
- Sử dụng biến môi trường cho mật khẩu
- Ví dụ Postgres và MariaDB (chỉnh host/port/db/user theo máy)

NỘI DUNG MẪU `.cursor/mcp.json`:
{
  "mcpServers": {
    "postgres": {
      "command": "mcp-postgres",
      "args": [
        "--host", "localhost",
        "--port", "5432",
        "--database", "docgo",
        "--user", "postgres",
        "--password", "${POSTGRES_PASSWORD}"
      ]
    },
    "mysql": {
      "command": "mcp-mysql",
      "args": [
        "--host", "localhost",
        "--port", "3306",
        "--database", "docgo",
        "--user", "root",
        "--password", "${MYSQL_PASSWORD}"
      ]
    }
  }
}

CÀI ĐẶT MCP SERVERS (chạy một lần):
- Postgres: `npm i -g @modelcontextprotocol/server-postgres`
- MySQL/MariaDB: `npm i -g @modelcontextprotocol/server-mysql`

SAU KHI CẤU HÌNH:
- Reload Cursor, xác nhận tools `postgres`/`mysql` xuất hiện
- Dùng tool để tạo bảng `snapshots`, `history_events` phục vụ service ở trên nếu cần
```
