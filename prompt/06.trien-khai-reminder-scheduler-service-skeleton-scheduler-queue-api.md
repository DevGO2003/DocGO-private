# Triển khai Reminder Scheduler Service (skeleton + scheduler/queue + API tạo/hủy)

## Prompt
```
Bạn là senior backend engineer. Hãy triển khai `reminder-scheduler-service` bằng FastAPI cho DocGO theo chuẩn dự án.

MỤC TIÊU (SCRUM-123): Skeleton + scheduler/queue stub + API tạo/huỷ (Reminder 01..03, Approval integration).

CHUẨN DỰ ÁN:
- Base path: `/api/v1/reminder-scheduler-service`
- Envelope `RestResponse` đồng nhất + quy tắc 204 trong body
- Docs `/docs#/` tiếng Việt với phần Đầu vào/Đầu ra
- Exception handlers 400/404/409/500; unexpected → `RestResponse` 500
- Cấu trúc: `main.py`, `routers/`, `schemas/`, `services/`, `workers/`, `config.py`, `README.md`, `How to run this microservice.md`
- Port cố định: 8007

TÍNH NĂNG/YÊU CẦU:
1) Scheduler nền (APScheduler/asyncio):
   - Lưu job metadata trong memory (stub), dễ thay bằng Redis/Kafka
   - Tick theo phút; quét queue để gửi reminders đến Notification Service
2) Queue stub:
   - In-memory queue hoặc Redis (tùy chọn), interface chung `ReminderQueue`
   - Producer: enqueue khi tạo reminder
   - Consumer: worker lấy job tới hạn và gửi event
3) APIs:
   - `POST /reminders` → tạo reminder
     Body: { contractId, type, dueAt: ISO-8601, recipients: [userId], channel: ["EMAIL","IN_APP","SMS"], note }
     Trả `RestResponse<Reminder>`
   - `GET /reminders` → phân trang + lọc (contractId, dueAt range, status)
   - `GET /reminders/{id}` → chi tiết reminder
   - `DELETE /reminders/{id}` → huỷ reminder (mark CANCELLED), dequeue
   - `POST /simulate-tick` → trigger tick thủ công (debug)
4) Event Payload Standard:
   - Phát `ReminderScheduled`, `ReminderCancelled`, `ReminderDue` (gửi sang Notification Service)
   - Thêm `correlationId` nếu đến từ Approval Service (Approval 03)

SCHEMAS GỢI Ý:
- Reminder { id, contractId, type, dueAt, status: PENDING|CANCELLED|SENT, recipients, channel, note, createdAt, createdBy }
- CreateReminderRequest, ReminderFilter, PaginatedResponse<T>

SERVICE LAYER:
- `ReminderService`:
  - `create_reminder(req) -> Reminder`
  - `get_reminder(id) -> Reminder`
  - `list_reminders(filters, pagination) -> PaginatedResponse<Reminder>`
  - `cancel_reminder(id) -> bool`
- `ReminderScheduler` (tick, enqueue/dequeue, due detection)
- `ReminderQueue` interface + `InMemoryReminderQueue` implementation

ROUTER LAYER:
- `router = APIRouter(prefix="/api/v1/reminder-scheduler-service", tags=["Reminder Scheduler Service"])`

DOCKER DEV:
- Dockerfile FastAPI chuẩn; compose dev mount code; port 8007

KIỂM THỬ NHANH:
- Tạo 2 reminders trong 2 phút tới → `/simulate-tick` hoặc chờ tick thật để phát `ReminderDue`
```

## Mục đích
- Cung cấp prompt tạo nhanh service reminder với scheduler/queue cơ bản, sẵn sàng nối Notification/Approval.

## Cách sử dụng
Copy Prompt và dán vào chat AI trong Cursor để sinh skeleton, services, routers, worker, và docs. Cập nhật cấu hình queue/Redis nếu triển khai thực tế.
