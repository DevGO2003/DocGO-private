Phân tích Use Cases có thể triển khai

Dựa trên cấu trúc database hiện tại của Contract Management Service và General File Management Service, đã phân tích các use case và đưa ra đánh giá khả năng triển khai:

CÓ THỂ TRIỂN KHAI NGAY

1. Tạo hợp đồng mới → Upload file mới, không chọn hợp đồng cũ
  • Kết quả: ContractMaster mới, version 1
  • Khả năng: HOÀN TOÀN KHẢ THI
  • Cách triển khai:
    • Upload file → General File Service
    • Tạo Contract mới với version = 1
    • Link file_id với contract.system_id
  • Độ phức tạp: Thấp
  • Thời gian ước tính: 30-45 phút
2. Upload file mới gắn vào hợp đồng cũ
  • Kết quả: ContractVersion mới
  • Khả năng: KHẢ THI (cần bổ sung logic)
  • Cách triển khai:
    • Upload file mới → General File Service
    • Tạo ContractVersion mới với version = n+1
    • Link với ContractMaster hiện có
  • Độ phức tạp: Trung bình
  • Thời gian ước tính: 45-60 phút
3. Chỉ sửa metadata → Update dữ liệu (không thay file)
  • Kết quả: ContractVersion mới với metadata khác
  • Khả năng: KHẢ THI
  • Cách triển khai:
    • Update contract fields
    • Tăng version number
    • Tạo event log
  • Độ phức tạp: Thấp
  • Thời gian ước tính: 20-30 phút

CẦN BỔ SUNG LOGIC

4. Sửa hợp đồng bị từ chối → Chọn bản Rejected để sửa
  • Kết quả: ContractVersion mới (n+1)
  • Khả năng: CẦN BỔ SUNG
  • Thiếu: Logic phân biệt status REJECTED và workflow sửa đổi
  • Cần bổ sung: Status workflow, rejection logic
5. Sửa hợp đồng đã duyệt → Chọn bản Approved → "Tạo bản sửa đổi"
  • Kết quả: ContractVersion mới (n+1, DRAFT)
  • Khả năng: CẦN BỔ SUNG
  • Thiếu: Workflow approval và logic tạo amendment
  • Cần bổ sung: Approval workflow, amendment logic
6. Clone từ version cũ → Chọn file cũ trong danh sách → "Tạo version"
  • Kết quả: ContractVersion mới từ nội dung cũ
  • Khả năng: CẦN BỔ SUNG
  • Thiếu: Logic clone và version management
  • Cần bổ sung: Version management, clone logic
7. Merge nhánh version → Hai version song song → chọn 1
  • Kết quả: ContractVersion chính thức mới
  • Khả năng: CẦN BỔ SUNG
  • Thiếu: Branch/merge logic hoàn toàn
  • Cần bổ sung: Branch/merge system hoàn toàn

Cấu trúc Database Contract Management Service

Tables chính:

  • contracts: Bảng chính lưu thông tin hợp đồng
  • contract_parties: Thông tin các bên tham gia
  • contract_events: Lịch sử sự kiện hợp đồng
  • contract_attachments: File đính kèm
  • contract_key_terms: Điều khoản chính
  • contract_favorable_clauses: Điều khoản có lợi
  • contract_unfavorable_clauses: Điều khoản bất lợi
  • contract_payment_details: Chi tiết thanh toán
  • contract_termination_conditions: Điều kiện chấm dứt

Key Features:

Versioning

Hỗ trợ version cho contracts

Soft Delete

Xóa mềm với is_deleted flag

JSON Fields

Lưu trữ dữ liệu phức tạp

Event Logging

Ghi lại mọi thay đổi

AI Integration

Hỗ trợ xử lý AI với processing_status

Điểm mạnh hiện tại

  • Database schema đã được thiết kế tốt với versioning
  • Có sẵn event logging system
  • Hỗ trợ JSON fields cho dữ liệu phức tạp
  • Integration với AI processing service

Điểm cần cải thiện

  • Cần bổ sung workflow management cho approval/rejection
  • Cần logic branch/merge cho version management
  • Cần clone functionality cho version cũ
  • Cần amendment workflow cho hợp đồng đã duyệt
