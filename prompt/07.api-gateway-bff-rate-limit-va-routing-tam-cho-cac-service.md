# API Gateway BFF: Thêm rate-limit + routing tạm cho các service

## Prompt
```
Bạn là senior fullstack. Hãy cập nhật `api-gateway-bff` (Next.js) để:
- Thêm rate limiting cơ bản cho các route API
- Thêm routing tạm (reverse proxy) tới các microservices đã có để FE tích hợp sớm

MỤC TIÊU (SCRUM-132): Rate-limit + routing tạm cho các service hiện có.

NGỮ CẢNH DỰ ÁN:
- BFF tại `backend/api-gateway-bff` (Next.js). FE cần gọi qua BFF: `/api/...`
- Các services cổng chuẩn:
  - user-management-service → http://localhost:8002
  - contract-management-service → http://localhost:8003
  - file-storage-asset-service → http://localhost:8012
  - ai-processing-service → http://localhost:8017
  - general-file-management-service → http://localhost:8018

YÊU CẦU CẬP NHẬT:
1) Rate limit (mức cơ bản):
   - 60 requests / minute / IP cho tất cả route `/api/*`
   - Sử dụng middleware trong Next.js (edge-friendly) hoặc thư viện `rate-limiter-flexible`
   - Khi vượt giới hạn: trả 429 với `RestResponse` schema (statusCode=429, shortMessage="Too Many Requests")

2) Routing tạm (proxy):
   Tạo endpoints BFF forward tới các service (giữ nguyên query/body):
   - `POST /api/ai/summarize` → 8017 `/api/v1/ai-processing-service/summarize`
   - `POST /api/ai/extract` → 8017 `/api/v1/ai-processing-service/extract`
   - `GET /api/files` → 8018 `/api/v1/general-file-management-service/files`
   - `GET /api/storage/files` → 8012 `/api/v1/file-storage-asset-service/files`
   - `POST /api/storage/files/{fileId}/signed-url` → 8012 `/api/v1/file-storage-asset-service/files/{fileId}/signed-url`
   - (tuỳ chọn) bổ sung routes cho user/contract nếu cần FE sớm

3) Chuẩn hoá response khi lỗi proxy:
   - Bắt lỗi fetch/timeout và trả `RestResponse` với `statusCode: 500` + `description` nêu rõ service downstream

4) Cấu hình CORS cho FE local

5) Tài liệu:
   - README trong BFF mô tả các route proxy mới + hạn mức rate-limit

GỢI Ý TRIỂN KHAI (Next.js):
- Tạo `middleware.ts` ở gốc BFF để limit `/api/*`
- Tạo file route handlers trong `pages/api/...` hoặc `app/api/...` (theo setup repo) để forward bằng `fetch`
- Đừng quên forward headers cần thiết (Authorization/X-Correlation-Id)
- Timeout hợp lý (10-15s) và map lỗi sang RestResponse

MẪU HANDLER (pseudo):
```
export default async function handler(req, res) {
  try {
    const url = `http://localhost:8017/api/v1/ai-processing-service/summarize`;
    const r = await fetch(url, { method: 'POST', headers: {...req.headers}, body: req.body, timeout: 15000 });
    const data = await r.json();
    res.status(200).json(data);
  } catch (e) {
    res.status(200).json({ apiVersion: 'v1', statusCode: 500, shortMessage: 'Internal Server Error', description: `Proxy ai-processing-service error: ${e}`, data: null, timestamp: new Date().toISOString(), requestId: crypto.randomUUID(), path: req.url });
  }
}
```

KIỂM THỬ NHANH:
- Gọi `/api/ai/summarize` qua BFF với file/text; quan sát rate-limit khi spam >60 req/phút
```

## Mục đích
- Giúp FE tích hợp sớm qua BFF có rate-limit và proxy chuẩn hoá lỗi
