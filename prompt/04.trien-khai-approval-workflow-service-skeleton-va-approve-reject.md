# Triển khai Approval Workflow Service (skeleton + approve/reject)

## Prompt
```
Bạn là senior backend engineer. Hãy triển khai microservice FastAPI `approval-workflow-service` cho DocGO theo chuẩn dự án.

MỤC TIÊU (SCRUM-122): Skeleton chuẩn + endpoints stub cho approve/reject (Approval 01/02/03, Reminder).

QUY TẮC CHUẨN HÓA (DocGO):
- Base path: `/api/v1/approval-workflow-service`
- Tài nguyên: số nhiều, kebab-case: `approvals`, `workflows`, `tasks`
- Envelope `RestResponse` thống nhất (apiVersion, statusCode, shortMessage, description, data, timestamp ISO-8601, requestId, path)
- Quy tắc 204: không dùng HTTP 204; trả HTTP 200 với `statusCode: 204` khi rỗng
- Docs ở `/docs#/` với summary/description tiếng Việt + phần Đầu vào/Đầu ra
- Exception handlers: map 400/404/409/500; lỗi không lường trước → `RestResponse` 500
- Cấu trúc: `main.py`, `routers/`, `schemas/`, `services/`, `config.py`, `README.md`, `How to run this microservice.md`
- Port cố định: 8006 (theo bảng port DocGO)

ENDPOINTS YÊU CẦU (stub chạy được):
1) `POST /workflows` – tạo workflow phê duyệt (sequential/parallel)
   - Body: { name, description, steps: [ { order, approverRole|approverId, mode: "SEQUENTIAL|PARALLEL" } ] }
   - Trả `RestResponse<Workflow>` với id sinh tự động
2) `GET /workflows/{id}` – lấy chi tiết workflow
3) `POST /approvals` – tạo approval instance cho `contractId` theo `workflowId`
   - Body: { contractId, workflowId, requesterId, note }
   - Trả `RestResponse<Approval>` (status = PENDING, currentStep)
4) `GET /approvals/{approvalId}` – lấy chi tiết approval + trạng thái từng bước
5) `PUT /approvals/{approvalId}/approve` – duyệt bước hiện tại
   - Body: { actorId, reason }
   - Kết quả: cập nhật step, nếu hoàn tất → status = APPROVED; phát event `ApprovalUpdated` + optional Reminder next
6) `PUT /approvals/{approvalId}/reject` – từ chối bước hiện tại
   - Body: { actorId, reason }
   - Kết quả: status = REJECTED; phát event `ApprovalUpdated`
7) `GET /approvals` – liệt kê approval theo bộ lọc (status, contractId, actorId) + phân trang chuẩn

SCHEMAS GỢI Ý (pydantic):
- Workflow { id, name, description, steps: [ { stepId, order, mode, approverRole, approverId } ], createdAt, createdBy }
- Approval { id, contractId, workflowId, status: PENDING|APPROVED|REJECTED, currentStep, steps: [ { stepId, status, actorId, decisionAt, reason } ], createdAt }
- CreateWorkflowRequest, CreateApprovalRequest, ApproveRequest, RejectRequest
- PaginatedResponse<T>

SERVICE LAYER:
- `ApprovalService`:
  - `create_workflow(req) -> Workflow`
  - `get_workflow(id) -> Workflow`
  - `create_approval(req) -> Approval`
  - `get_approval(approval_id) -> Approval`
  - `approve(approval_id, actor_id, reason) -> Approval`
  - `reject(approval_id, actor_id, reason) -> Approval`
  - `list_approvals(filters, pagination) -> PaginatedResponse[Approval]`
- Validate actor/role theo `approverRole|approverId` của step hiện tại
- Phát event theo Event Payload Standard (`ApprovalUpdated`, `ContractProcessed`) sau approve/reject
- Gợi ý: tích hợp Reminder Service (đặt nhắc bước tiếp theo nếu chưa hoàn tất)

ROUTER LAYER:
- `router = APIRouter(prefix="/api/v1/approval-workflow-service", tags=["Approval Workflow Service"])`
- Thêm summary/description tiếng Việt, mô tả Input/Output theo chuẩn dự án

EXCEPTION/ENVELOPE:
- Dùng `RestResponse` như các service FastAPI trong repo
- Gắn exception handlers giống `user-management-service`

DOCKER DEV:
- Dockerfile FastAPI chuẩn; mount code qua docker-compose dev; port 8006

TÀI LIỆU:
- README + How-to-run (env, chạy uvicorn, docs URL)

KIỂM THỬ NHANH:
- Tạo 1 workflow 2 bước (SEQUENTIAL), tạo 1 approval cho `contractId` bất kỳ; gọi approve 2 lần để chuyển APPROVED
```

## Mục đích
- Cung cấp prompt triển khai nhanh service phê duyệt với endpoints approve/reject chạy được theo chuẩn DocGO.

## Cách sử dụng
Copy nội dung Prompt dán vào chat AI trong Cursor để tạo skeleton, routers, schemas, services, Docker và tài liệu theo đúng chuẩn. Chạy và kiểm thử bằng `/docs#/`.
